# VSG Simulator

Программный комплекс моделирования и анализа сигналов векторного генератора.
Веб-приложение выполняет полный тракт формирования векторного сигнала, вносит
искажения реального прибора, строит диаграммы и рассчитывает метрики качества.

Сборка не требуется: приложение написано на чистых модулях ECMAScript и
работает без Node.js, npm и внешних библиотек.

## Запуск на своём компьютере

Модули ECMAScript не загружаются по протоколу `file://`, поэтому нужен любой
статический сервер. Например, встроенный сервер Python:

```bash
python -m http.server 8010
```

Затем открыть `http://127.0.0.1:8010/`. Проверка вычислительного ядра доступна
по адресу `http://127.0.0.1:8010/tests/`.

## Развёртывание на Vercel

Node.js для этого не нужен, платные тарифы и сертификаты тоже: сертификат HTTPS
для адреса вида `имя.vercel.app` Vercel выпускает автоматически.

1. Создать репозиторий и отправить в него содержимое этой папки:

```bash
git init
git add .
git commit -m "VSG Simulator"
git branch -M main
git remote add origin https://github.com/ПОЛЬЗОВАТЕЛЬ/РЕПОЗИТОРИЙ.git
git push -u origin main
```

2. На `vercel.com` выбрать **Add New → Project**, указать этот репозиторий.
3. В настройках сборки выбрать framework **Other**, поля Build Command и Output
   Directory оставить пустыми — файлы отдаются как есть.
4. Нажать **Deploy**.

Приложение полностью работает на стороне браузера, поэтому серверные функции
не используются и расход ресурсов тарифа сводится к раздаче статических файлов.

## Проверка корректности

Реализованы две независимые проверки.

**Самотест в браузере** (`tests/`) сверяет расчёт с теорией: период и баланс
последовательностей PRBS, нормировку созвездий и характеристики фильтра,
совпадение MER с заданным отношением сигнал/шум, соответствие EVM теоретическому
значению, монотонность ACPR по отступу от насыщения усилителя, воспроизводимость
результата при одинаковом зерне генератора.

**Эталонная модель на Python** повторяет тракт средствами NumPy, включая
генератор псевдослучайных чисел, поэтому результаты сравниваются не статистически,
а поразрядно:

```bash
python reference/model.py          # таблица результатов по режимам
python reference/model.py --json   # то же в формате JSON для сверки
python reference/model.py --figures  # рисунки для пояснительной записки
```

Сверка двенадцати режимов по пяти параметрам показала максимальное относительное
расхождение 1,5 · 10⁻⁶, обусловленное округлением при выводе.

## Принятые допущения модели

Сигнал рассчитывается в виде комплексной огибающей. Несущая частота задаётся
параметром и используется при разметке оси частот: прямая дискретизация колебания
гигагерцевого диапазона потребовала бы частоты отсчётов в несколько гигагерц.
Так же построен тракт формирования и в реальном векторном генераторе.

Отношение сигнал/шум задаётся в полосе символьной скорости, поэтому измеренное
значение MER совпадает с заданным. Уровень ACPR при включённом шуме ограничен
именно шумом, а не нелинейностью усилителя.

Предустановки стандартов LTE и Wi-Fi упрощены: задаются типовая схема модуляции,
полоса и пороги допустимой EVM. Полная кадровая структура OFDM не моделируется,
в техническом задании эти предустановки отмечены как необязательные.

## Экспорт

Графики сохраняются в PNG поодиночке и в PDF целиком. Отчёт PDF содержит таблицу
параметров, результаты измерений с заключением «годен / не годен» и все выбранные
диаграммы. Данные I/Q выгружаются в CSV и в WAV: в файле WAV левый канал содержит
синфазную составляющую, правый — квадратурную, такой файл читают программы работы
с SDR. Конфигурация параметров сохраняется и загружается в формате JSON.
